TASCA-03 · Arrays, Funcions i Formularis en PHP

M613-B1 · Esteve Amargant · Explicacions pas a pas de com s'ha fet cada exercici i per què.

0.Entorn i estructura

L'enunciat demana una petita web en PHP amb Bootstrap i 4 exercicis (Capitals, Temperatures, Arrays associatius i Acadèmia d'idiomes). Els exercicis han de compartir una capçalera, un peu i un fitxer de funcions mitjançant includes. Tot s'ha fet sense base de dades: l'estat es guarda en camps ocults dels formularis.

Estructura de fitxers

Tasca 3/
├── README.md                  Instruccions d'instal·lació
├── explicacions.html          Aquest document
└── src/
    ├── assets/css/styles.css  Estils propis (complementen Bootstrap)
    ├── includes/
    │   ├── header.php         <head>, Bootstrap i menú
    │   ├── footer.php         Peu i JS de Bootstrap
    │   └── functions.php      TOTES les funcions dels exercicis
    ├── ex1.php                Capitals Europees
    ├── ex2.php                Anàlisi de Temperatures
    ├── ex3.php                Arrays Associatius
    ├── ex4.php                Acadèmia d'Idiomes
    └── index.php              Pàgina d'inici

Com s'executa

Fem servir el docker-compose.yml de la carpeta del mòdul. Aixeca un contenidor php:8.2-apache al port 8080 i munta tota la carpeta a /var/www/html:

cd "Desenvolupament web en entrorn servidor"
docker compose up

URL: http://127.0.0.1:8080/Tasca%203/src/index.php

Per què 127.0.0.1 i no localhost?

Des de Windows, localhost es resol primer per IPv6 (::1). En aquest equip, ::1:8080 l'escolta el relay de WSL, que porta a un altre servidor de dins d'Ubuntu, i aquest respon amb un 404. En canvi, 127.0.0.1 (IPv4) arriba directament al contenidor de Docker. Ho vam diagnosticar comparant curl http://127.0.0.1:8080/... (200) amb curl http://[::1]:8080/... (404).

Què passa quan s'envia un formulari

Navegador omple el formulari→ GET/POST a action="" (el mateix fitxer)→ PHP llegeix $_GET / $_POST→ Valida i calcula amb functions.php→ Genera HTML nou amb l'estat en camps ocults

1.Esquelet comú: header, footer i functions

Abans dels exercicis es crea la base que comparteixen totes les pàgines: header.php (obre l'HTML, carrega Bootstrap i pinta el menú), footer.php (tanca l'HTML) i functions.php (totes les funcions). Així no es repeteix codi i, si canvies el menú, només el toques en un lloc.

include vs require vs require_once

Totes aquestes ordres "copien" un altre fitxer PHP dins del fitxer actual, com si l'haguessis enganxat allà. La diferència és què passa quan alguna cosa va malament:

OrdreSi el fitxer no existeix…Si ja s'ha inclòs abans…
includeAvís (warning) i la pàgina continuaEl torna a incloure
include_onceAvís i continuaNo el torna a incloure
requireError fatal: la pàgina s'aturaEl torna a incloure
require_onceError fatalNo el torna a incloure

Fem servir require_once per dos motius:

  • Sense aquests fitxers la pàgina no té sentit, així que és millor que s'aturi que no pas que surti mig trencada.
  • Si functions.php es carregués dues vegades, PHP donaria l'error Cannot redeclare function e(). El _once ho evita.

__DIR__ per a les rutes

__DIR__ és una constant màgica que conté la carpeta del fitxer on està escrita. Amb __DIR__ . '/includes/header.php' la ruta és absoluta i funciona independentment de des d'on s'executi el script. Una ruta relativa ('includes/header.php') depèn del directori de treball actual, que pot canviar.

L'ordre dins de cada pàgina

Totes les pàgines (index.php, ex1.php…) segueixen el mateix patró:

<?php
require_once __DIR__ . '/includes/functions.php'; // 1. funcions (el header ja les necessita)
$titol = 'Capitals Europees';                      // 2. variables per al header

// 3. LÒGICA: llegir GET/POST, validar, calcular

require_once __DIR__ . '/includes/header.php';     // 4. HTML d'obertura + menú
?>
<!-- 5. contingut HTML de la pàgina -->
<?php require_once __DIR__ . '/includes/footer.php'; ?> // 6. HTML de tancament

Cal fixar-se en dues coses:

  • Els fitxers inclosos comparteixen les variables de la pàgina que els inclou. Per això header.php pot llegir $titol.
  • La lògica va abans de l'HTML. Quan es comença a pintar la pàgina, tots els càlculs i errors ja estan fets. Això separa "pensar" de "mostrar".

A header.php, $titol = $titol ?? 'PHP Exercicis'; fa servir l'operador ?? (null coalescing): si $titol no existeix o és null, agafa el valor de la dreta.

e() i htmlspecialchars(): protecció contra XSS

El PDF demana escapar tota la sortida. Si un usuari escriu <script>alert(1)</script> en un formulari i el mostrem tal qual, el navegador l'executaria. Això és un atac XSS (Cross-Site Scripting). htmlspecialchars() converteix els caràcters perillosos en entitats HTML:

CaràcterEs converteix en
<&lt;
>&gt;
&&amp;
"&quot;
'&#039; (només amb ENT_QUOTES)

Com que s'ha d'escriure moltíssimes vegades, hem fet una funció curta:

function e($text): string
{
    return htmlspecialchars((string) $text, ENT_QUOTES, 'UTF-8');
}
  • ENT_QUOTES escapa també les cometes simples. És important quan el valor va dins d'un atribut: value="<?= e($x) ?>".
  • 'UTF-8' indica la codificació, perquè els accents (à, è, ç…) es tractin bé.
  • (string) permet passar-hi números sense problemes.

També hi ha mostrarErrors(array $errors) i mostrarExit(string $missatge), que pinten alertes de Bootstrap (vermella i verda). Es fan servir a tots els exercicis.

Menú amb l'enllaç actiu

$paginaActual = basename($_SERVER['PHP_SELF']);   // "ex1.php"
...
<a class="nav-link <?= $fitxer === $paginaActual ? 'active' : '' ?>" ...>

$_SERVER['PHP_SELF'] és la ruta del script que s'està executant (/Tasca 3/src/ex1.php) i basename() en treu només el nom. Si coincideix amb l'enllaç, se li posa la classe active de Bootstrap.

Sintaxi alternativa dins l'HTML

Quan PHP i HTML van barrejats, és més llegible fer servir:

<?php foreach ($menu as $fitxer => $text): ?>
    <li><?= e($text) ?></li>
<?php endforeach; ?>
  • <?= ... ?> equival a <?php echo ... ?>.
  • foreach (...): … endforeach;, if (...): … else: … endif; substitueixen les claus { }, que dins l'HTML es perden fàcilment.

2.Exercici 1: Capitals Europees

Què demana: donat un array associatiu país => capital, crear una funció que el retorni ordenat per capital mantenint el país, amb cerca parcial sense distingir majúscules i filtre per la lletra inicial del país.

Funcions creades: ordenarPerCapital(), cercarPaisOCapital(), filtrarPerLletra() i lletresInicials().

A la pàgina, les tres operacions s'encadenen. Cada una rep el resultat de l'anterior:

$resultat = ordenarPerCapital($ceu);
$resultat = cercarPaisOCapital($resultat, $cerca);
$resultat = filtrarPerLletra($resultat, $lletra);

Per què asort i no sort

FuncióOrdena perConserva les claus?Ordre
sortvalor❌ les substitueix per 0, 1, 2…ascendent
rsortvalor❌descendent
asortvalor✅ascendent
arsortvalor✅descendent
ksortclau✅ascendent
krsortclau✅descendent
usort / uasortfunció pròpia❌ / ✅el que diguis

Volem ordenar per capital (el valor) sense perdre el país (la clau): asort. Amb sort obtindríem [0 => "Amsterdam", 1 => "Athens", …] i ja no sabríem de quin país és cada capital.

function ordenarPerCapital(array $paisos): array
{
    asort($paisos, SORT_STRING | SORT_FLAG_CASE);
    return $paisos;
}

Els flags SORT_STRING | SORT_FLAG_CASE fan que compari com a text i sense distingir majúscules. Sense SORT_FLAG_CASE, les majúscules van abans que les minúscules ("Zagreb" < "amsterdam").

"Retornar" l'array: pas per valor

asort modifica l'array que rep, però l'enunciat diu que la funció l'ha de retornar. Això funciona perquè a PHP els arrays es passen per valor: la funció rep una còpia, la modifica i la retorna. L'original $ceu no canvia.

function f(array $a)  { ... }   // per valor: treballa amb una còpia
function g(array &$a) { ... }   // per referència (&): modifica l'original

array_filter amb funcions fletxa

array_filter recorre l'array i només es queda els elements per als quals la funció retorna true. Les claus es conserven. El tercer paràmetre indica què rep la funció:

ModeLa funció repOn el fem servir
(per defecte)el valor—
ARRAY_FILTER_USE_KEYla claufiltre per lletra inicial del país
ARRAY_FILTER_USE_BOTHvalor i claucerca per país o capital
function cercarPaisOCapital(array $paisos, string $text): array
{
    $text = trim($text);
    if ($text === '') {
        return $paisos;                       // sense text, no filtrem
    }
    return array_filter(
        $paisos,
        fn($capital, $pais) => stripos($pais, $text) !== false || stripos($capital, $text) !== false,
        ARRAY_FILTER_USE_BOTH
    );
}

fn(...) => expressió és una funció fletxa (PHP 7.4+): una funció anònima d'una sola expressió que retorna el resultat directament. A més, pot fer servir variables de fora (com $text) sense necessitat de use.

Cerca parcial: stripos i la trampa del 0

stripos($pajar, $agulla) retorna la posició on troba el text, o false si no el troba. La i vol dir case-insensitive (no distingeix majúscules).

Compte: cal comparar amb !== false

Si la coincidència és al principi, stripos("Paris", "par") retorna 0. Amb una comparació feble, 0 == false és cert, i "Paris" no sortiria als resultats. !== compara també el tipus: 0 !== false és cert, que és el que volem.

La inicial del país

$pais[0] és el primer caràcter de l'string. lletresInicials() recull totes les inicials, en treu les repetides amb array_unique() i les ordena amb sort(). Aquí sort va bé perquè les claus no importen. Aquesta llista omple el <select> del filtre.

Per què GET i com es "recorda" el formulari

El PDF diu: GET per a cerques i filtres. Amb GET, els paràmetres van a la URL (ex1.php?cerca=par&lletra=F). Així es pot fer un favorit de la cerca, compartir-la o tornar-hi amb el botó "enrere". A més, una cerca no modifica res, i aquest és el significat de GET a HTTP.

  • action="" envia el formulari al mateix fitxer.
  • value="<?= e($cerca) ?>" torna a omplir el camp amb el que havies escrit.
  • <?= $l === $lletra ? 'selected' : '' ?> deixa marcada l'opció escollida.

Validació

No ens podem fiar de res que arribi per $_GET, perquè l'usuari pot escriure la URL a mà. Per això:

if ($lletra !== '' && !in_array($lletra, $lletres, true)) {
    $errors[] = 'La lletra seleccionada no és vàlida.';
    $lletra = '';
}

El true final d'in_array activa la comparació estricta (tipus i valor). També limitem la cerca a 50 caràcters amb mb_strlen(), que compta caràcters i no bytes (una "à" ocupa 2 bytes en UTF-8).

Comprovat

Sense filtres: Amsterdam, Athens, Berlin, Bratislava… (com a la captura del PDF). Cerca "PAR" → France/Paris. Lletra "S" → Slovakia, Slovenia, Spain, Sweden. <script> a la cerca → surt escapat.

3.Exercici 2: Anàlisi de Temperatures

Què demana: funcions per convertir de °F a °C, calcular la mitjana, la mediana, el top 5 més altes i més baixes, i la màxima i la mínima. També un formulari per afegir temperatures i triar l'escala, amb els resultats en una taula i un gràfic opcional.

Funcions creades: fahrenheitACelsius(), formatTemperatura(), calcularMitjana(), calcularMediana(), temperaturesMesAltes(), temperaturesMesBaixes(), temperaturaMaxima(), temperaturaMinima() i validarTemperatura().

El problema: HTTP no té memòria

Cada petició executa el PHP des de zero. Les variables no sobreviuen d'una petició a la següent. Si afegeixes 90 °F i després 95 °F, en la segona petició el servidor ja no recorda el 90. Hi ha diverses maneres de guardar l'estat: sessions, cookies, una base de dades… L'enunciat demana fer-ho amb camps ocults.

Camps ocults amb name="temps[]"

Cada formulari porta dins totes les temperatures actuals:

<input type="hidden" name="temps[]" value="78">
<input type="hidden" name="temps[]" value="60">
<input type="hidden" name="temps[]" value="62">
...

Els [] al final del name són clau: PHP ajunta tots els camps amb aquest nom en un array, i $_POST['temps'] ja és ["78", "60", "62", …]. El cicle és aquest:

Pàgina amb 30 temps ocults→ Envies 90→ PHP llegeix els 30 + afegeix 90→ Pàgina nova amb 31 temps ocults→ …

Per distingir la primera visita de les següents:

if ($_SERVER['REQUEST_METHOD'] === 'POST') {
    // recuperar l'estat dels camps ocults i processar l'acció
} else {
    $temperatures = $temperaturesInicials;   // primera visita (GET): dades del PDF
    $escala = 'F';
}

"Ocult" no vol dir "segur"

Amb l'inspector del navegador (F12) qualsevol pot editar un camp ocult. Per això també validem l'estat, no només el camp que escriu l'usuari:

function validarTemperatura($valor): ?float
{
    $temp = filter_var($valor, FILTER_VALIDATE_FLOAT);
    if ($temp === false || $temp < -100 || $temp > 200) {
        return null;
    }
    return $temp;
}
  • filter_var(..., FILTER_VALIDATE_FLOAT) retorna el número com a float, o false si no ho és. És més fiable que is_numeric, que accepta coses com "1e3" o espais.
  • El tipus de retorn ?float vol dir "float o null".
  • Si un valor desat no és vàlid, es descarta i es mostra un avís. Si no en queda cap de vàlid, es restauren les dades inicials.

Dos formularis i botons amb valor

  • Afegir: camp nova i botó <button name="accio" value="afegir">.
  • Escala: dos botons type="submit" amb el mateix name="escala" i valors F i C. Només s'envia el valor del botó que cliques, així que no cal JavaScript.

Tots dos formularis porten els camps ocults. Si un no els portés, en fer-lo servir es perdrien les temperatures afegides. El formulari d'afegir també porta l'escala actual en un camp ocult, perquè no torni a Fahrenheit en afegir.

Guardar en °F i convertir només en mostrar

Els càlculs es fan sempre amb els valors originals en °F. La conversió només es fa en el moment de pintar:

function fahrenheitACelsius(float $f): float
{
    return round(($f - 32) * 5 / 9, 2);       // C = (F − 32) × 5/9, 2 decimals
}

function formatTemperatura(float $f, string $escala): string
{
    $valor = $escala === 'C' ? fahrenheitACelsius($f) : $f;
    return number_format($valor, 2, '.', '') . '°' . $escala;   // "70.42°F"
}

Si convertíssim primer cada temperatura i l'arrodoníssim a 2 decimals, els càlculs posteriors (com la mitjana) acumularien petits errors d'arrodoniment. Tenir una única unitat interna és una pràctica habitual: guardar en una unitat i convertir només en la presentació.

Les funcions estadístiques

CàlculCom
Mitjanaarray_sum($t) / count($t)
Màxima / mínimamax($t) / min($t)
5 més altessort($t) i array_slice($t, -5): els 5 últims
5 més baixessort($t) i array_slice($t, 0, 5): els 5 primers
MedianaOrdenar i agafar el valor del mig (vegeu a sota)

La mediana és el valor central de la llista ordenada. Si el nombre d'elements és parell, no hi ha un valor central únic i es fa la mitjana dels dos del mig:

function calcularMediana(array $temps): float
{
    if (empty($temps)) return 0.0;
    sort($temps);
    $n = count($temps);
    $meitat = intdiv($n, 2);                  // divisió entera: intdiv(31, 2) = 15

    if ($n % 2 === 0) {                       // parell: mitjana dels dos centrals
        return ($temps[$meitat - 1] + $temps[$meitat]) / 2;
    }
    return $temps[$meitat];                   // senar: el del mig
}

Exemple: amb 30 temperatures, $meitat = 15 i es fa la mitjana de les posicions 14 i 15. Amb 31 (en afegir-ne una), és directament la posició 15.

Totes aquestes funcions reben l'array per valor, així que el sort() intern no desordena l'array de la pàgina.

Gràfic opcional amb Chart.js

Per passar dades de PHP a JavaScript es fa servir json_encode(), que converteix un array de PHP en un array de JavaScript vàlid:

const dades = <?= json_encode($dadesGrafic, JSON_HEX_TAG) ?>;   // [78, 60, 62, ...]

JSON_HEX_TAG converteix < i > en < i >. Així un valor no podria contenir mai </script> i tancar l'etiqueta abans d'hora. És l'equivalent de htmlspecialchars dins de JavaScript.

4.Exercici 3: Arrays Associatius

Què demana: combinar $keys i $values de dues maneres (amb bucles i amb array_combine()) per obtenir ["first" => "dinosaur", "second" => "pig", "third" => "platypus"], i un formulari per afegir, modificar i eliminar parelles.

Funcions creades: combinarAmbBucles(), combinarAmbArrayCombine(), formatArrayAssociatiu(), validarClau(), validarValor(), afegirParella(), modificarParella(), eliminarParella() i campsOcults().

Combinar amb bucles

$keys   = ["field1" => "first",    "field2" => "second", "field3" => "third"];
$values = ["field1value" => "dinosaur", "field2value" => "pig", "field3value" => "platypus"];

Les claus originals (field1, field1value…) no ens serveixen, perquè volem els valors de $keys com a claus noves. Com que els dos arrays tenen claus diferents, no els podem recórrer junts per clau. La solució és array_values(), que els converteix en llistes indexades:

function combinarAmbBucles(array $keys, array $values): array
{
    if (count($keys) !== count($values)) {
        throw new InvalidArgumentException('Els dos arrays han de tenir el mateix nombre d\'elements.');
    }
    $llistaClaus  = array_values($keys);      // [0 => "first", 1 => "second", 2 => "third"]
    $llistaValors = array_values($values);    // [0 => "dinosaur", 1 => "pig", 2 => "platypus"]

    $resultat = [];
    for ($i = 0; $i < count($llistaClaus); $i++) {
        $resultat[$llistaClaus[$i]] = $llistaValors[$i];   // "first" => "dinosaur"
    }
    return $resultat;
}

Combinar amb array_combine()

array_combine($a, $b) fa exactament el mateix en una línia: agafa els valors del primer array com a claus i els valors del segon com a valors. Les claus dels dos arrays d'entrada s'ignoren. Si les mides no coincideixen, PHP 8 llança un ValueError. Per això ho comprovem abans i llancem el nostre propi error, amb un missatge clar.

La pàgina compara els dos resultats amb ===, que vol dir mateixes claus, mateixos valors i mateix ordre, i mostra un indicador verd si coincideixen.

Gestió d'errors amb excepcions

El PDF demana gestionar possibles errors. Les funcions no imprimeixen res: si alguna cosa no quadra, llancen una excepció:

function afegirParella(array $parelles, string $clau, string $valor): array
{
    if (array_key_exists($clau, $parelles)) {
        throw new InvalidArgumentException("La clau \"$clau\" ja existeix.");
    }
    $parelles[$clau] = $valor;
    return $parelles;
}

La pàgina les captura i decideix com mostrar-les:

try {
    switch ($accio) {
        case 'afegir':    $parelles = afegirParella($parelles, $clau, $valor);    break;
        case 'modificar': $parelles = modificarParella($parelles, $clau, $valor); break;
        case 'eliminar':  $parelles = eliminarParella($parelles, $clau);          break;
        default: throw new InvalidArgumentException('Acció desconeguda.');
    }
} catch (InvalidArgumentException $ex) {
    $errors[] = $ex->getMessage();
}

Avantatges d'aquest patró:

  • Les funcions són reutilitzables: no saben res de Bootstrap ni d'HTML.
  • Quan es llança una excepció, l'execució salta directament al catch. L'array no s'arriba a modificar, així que no queda a mitges.
  • El mateix patró es reutilitza a l'exercici 4.

array_key_exists, isset i unset

  • array_key_exists($clau, $arr) indica si la clau existeix, sigui quin sigui el valor.
  • isset($arr[$clau]) retorna false si la clau existeix però el valor és null. Per comprovar "existeix aquesta clau?" és més correcte array_key_exists.
  • unset($arr[$clau]) elimina la parella de l'array.

campsOcults(): guardar qualsevol array

A l'exercici 2 els camps ocults s'escrivien a mà amb un foreach. Per als arrays associatius (i després la matriu) es va crear una funció genèrica i recursiva:

function campsOcults(string $nom, array $dades): string
{
    $html = '';
    foreach ($dades as $clau => $valor) {
        $nomCamp = $nom . '[' . $clau . ']';
        if (is_array($valor)) {
            $html .= campsOcults($nomCamp, $valor);   // es crida a si mateixa
        } else {
            $html .= '<input type="hidden" name="' . e($nomCamp) . '" value="' . e($valor) . '">' . "\n";
        }
    }
    return $html;
}
CridaGenera
campsOcults('parelles', ['first' => 'dinosaur'])name="parelles[first]" value="dinosaur"
campsOcults('alumnes', ['Bàsic' => ['Anglès' => ['Anna']]])name="alumnes[Bàsic][Anglès][0]" value="Anna"

Quan PHP rep parelles[first]=dinosaur, reconstrueix automàticament l'array associatiu a $_POST['parelles']. Amb diversos nivells de [ ], construeix arrays niats.

Un formulari per fila

Cada fila de la taula és un formulari independent:

<form action="" method="post">
    <?= campsOcults('parelles', $parelles) ?>               <!-- tot l'estat -->
    <input type="hidden" name="clau" value="second">        <!-- quina fila és -->
    <input type="text"   name="valor" value="pig">           <!-- editable -->
    <button name="accio" value="modificar">Modificar</button>
    <button name="accio" value="eliminar">Eliminar</button>

El valor del botó clicat arriba com a $_POST['accio'], i el switch decideix què fer.

Validar les claus amb una expressió regular

La clau acaba dins de name="parelles[...]", així que no pot contenir qualsevol cosa: un ] trencaria l'estructura. Fem servir:

preg_match('/^[\p{L}\p{N}_\- ]{1,30}$/u', $clau) === 1

5.Exercici 4: Gestió d'Acadèmia d'Idiomes

Què demana: una matriu de nivells (Bàsic, Mitjà, Perfeccionament) × idiomes (Anglès, Francès, Alemany, Rus), les sis funcions d'estadística, formularis per afegir, eliminar i moure alumnes, estadístiques en taula i una cerca d'alumne pel nom que indiqui a quin grup pertany.

Funcions creades: les sis demanades (comptarTotalAlumnes, comptarTotalPerIdioma, buscarGrupMesNombros, buscarGrupMenysNombros, calcularMitjanaPerNivell, calcularMitjanaPerIdioma) i, a més, crearAcademiaBuida, validarNomAlumne, reconstruirAcademia, comptarTotalPerNivell, buscarGrupAlumne, cercarAlumne, llistarAlumnes, afegirAlumne, eliminarAlumne i moureAlumne.

La matriu (array multidimensional)

$academia = [
    'Bàsic' => [
        'Anglès'  => ['Anna', 'Marc', 'Laia', 'Pau', 'Júlia'],
        'Francès' => ['Jordi', 'Marta'],
        'Alemany' => ['Núria', 'Oriol', 'Clara'],
        'Rus'     => ['Pol'],
    ],
    'Mitjà' => [ ... ],
    'Perfeccionament' => [ ... ],

$academia['Bàsic']['Anglès']      // ['Anna', 'Marc', 'Laia', 'Pau', 'Júlia']
$academia['Bàsic']['Anglès'][0]   // 'Anna'
count($academia['Bàsic']['Anglès']) // 5 alumnes en aquest grup

Conceptualment és una taula de 2 dimensions (files = nivells, columnes = idiomes), però cada cel·la és una llista de noms, per tant són 3 nivells d'array. Desar els noms, i no només un número, és el que permet cercar, eliminar i moure alumnes concrets.

Les funcions estadístiques: foreach niats

Totes segueixen el mateix esquema. Només canvia què acumulen:

Reconstruir l'estat: el problema dels grups buits

campsOcults('alumnes', $academia) genera camps com alumnes[Bàsic][Anglès][0]=Anna, i PHP els torna a convertir en matriu. Però un grup sense alumnes no genera cap camp, i en tornar desapareixeria de la matriu. Les taules es quedarien sense aquella columna.

Per això reconstruirAcademia() parteix d'una matriu buida completa i hi va afegint només el que és vàlid:

function reconstruirAcademia($dades, array $nivells, array $idiomes, int &$descartats = 0): array
{
    $academia = crearAcademiaBuida($nivells, $idiomes);   // tots els grups, buits
    $descartats = 0;

    foreach ((array) $dades as $nivell => $perIdioma) {
        foreach ((array) $perIdioma as $idioma => $noms) {
            if (!in_array($nivell, $nivells, true) || !in_array($idioma, $idiomes, true)) {
                $descartats++;                             // nivell/idioma inventat
                continue;
            }
            foreach ((array) $noms as $nom) {
                if (!is_string($nom) || !validarNomAlumne($nom) || buscarGrupAlumne($academia, $nom) !== null) {
                    $descartats++;                         // nom invàlid o duplicat
                    continue;
                }
                $academia[$nivell][$idioma][] = $nom;
            }
        }
    }
    return $academia;
}
  • (array) $dades força que sigui un array, encara que algú enviï un text en lloc d'un array.
  • int &$descartats es passa per referència: la funció modifica directament la variable de qui la crida. És una manera de "retornar" un segon valor (el comptador de descartats) a més de la matriu.

POST i GET a la mateixa pàgina

  • Afegir, eliminar i moure modifiquen dades, així que van per POST.
  • Cercar és una consulta, així que va per GET.

Com que l'estat ha de viatjar en tots dos casos, el formulari de cerca també porta els camps ocults (en aquest cas, a la URL). Aquesta línia tria d'on es llegeix l'estat:

$peticio = $_SERVER['REQUEST_METHOD'] === 'POST' ? $_POST : $_GET;

if (isset($peticio['estat'])) {
    $academia = reconstruirAcademia($peticio['alumnes'] ?? [], $nivells, $idiomes, $descartats);
} else {
    $academia = $academiaInicial;           // primera visita
}

El camp ocult estat=1 és un "marcador". Sense ell, no es podria distingir la primera visita (cal carregar les dades inicials) d'una acadèmia on s'han eliminat tots els alumnes (no arriba cap camp alumnes, però l'acadèmia ha d'estar buida, no reiniciada).

L'HTML de l'estat es genera una sola vegada a $estat i es reutilitza en els quatre formularis.

Noms únics i funcions mb_

Decisió de disseny: no hi pot haver dos alumnes amb el mateix nom (sense distingir majúscules). Així:

  • Eliminar i moure només necessiten el nom, que es tria d'un <select>.
  • buscarGrupAlumne($academia, $nom) respon directament a l'enunciat: "cercar un alumne pel nom i mostrar a quin grup pertany".
if (mb_strtolower($alumne) === mb_strtolower($nom)) {
    return ['nivell' => $nivell, 'idioma' => $idioma, 'nom' => $alumne];
}

Es fa servir mb_strtolower i no strtolower perquè els noms porten accents (Júlia, Sílvia, Lucía). Les funcions mb_ (multibyte) entenen UTF-8. strtolower treballa byte a byte i no converteix bé "Í" a "í". Pel mateix motiu, la cerca parcial (cercarAlumne) fa servir mb_stripos.

El nom es valida amb /^\p{L}[\p{L} '\-]{1,39}$/u: ha de començar per lletra i pot contenir lletres, espais, apòstrof i guió (per exemple Maria-Pia o D'Arcy), fins a 40 caràcters.

Eliminar d'una llista: array_search i array_splice

$posicio = array_search($grup['nom'], $alumnes, true);   // on és? (p. ex. 2)
array_splice($alumnes, $posicio, 1);                      // treu 1 element en aquesta posició
Per què no unset?

unset($alumnes[2]) deixaria un forat als índexs: [0 => 'Anna', 1 => 'Marc', 3 => 'Pau']. array_splice reindexa la llista (0, 1, 2). Per a un array associatiu (exercici 3) unset és correcte, perquè les claus tenen significat. Per a una llista ordenada és millor array_splice.

Moure = eliminar + afegir

function moureAlumne(array $academia, string $nom, string $nivellDesti, string $idiomaDesti): array
{
    $grup = buscarGrupAlumne($academia, $nom);
    if ($grup === null)                         throw new InvalidArgumentException("No s'ha trobat l'alumne \"$nom\".");
    if (!isset($academia[$nivellDesti][$idiomaDesti])) throw new InvalidArgumentException('El grup destí no existeix.');
    if ($grup['nivell'] === $nivellDesti && $grup['idioma'] === $idiomaDesti)
        throw new InvalidArgumentException("{$grup['nom']} ja és al grup $nivellDesti - $idiomaDesti.");

    $academia = eliminarAlumne($academia, $grup['nom']);       // reutilitza
    $academia[$nivellDesti][$idiomaDesti][] = $grup['nom'];
    return $academia;
}

Es reutilitza eliminarAlumne() en lloc de repetir codi. Abans es comprova tot el que podria anar malament: que l'alumne existeixi, que el grup destí existeixi i que no sigui el mateix grup.

Ressaltar els resultats de la cerca a la matriu

$nomsTrobats = array_column($resultatsCerca, 'nom');   // ['Ferran', 'Joan', 'Kilian', ...]
...
